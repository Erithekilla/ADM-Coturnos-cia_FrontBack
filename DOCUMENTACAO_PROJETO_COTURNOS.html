1. Visão Geral do Projeto

O Coturnos & Cia é uma plataforma de comércio eletrônico de alta performance voltada para calçados operacionais, coturnos táticos militares, borzeguins de segurança e acessórios técnicos. O ecossistema é projetado sob os pilares da alta disponibilidade, segurança cibernética defensiva (alinhada às diretrizes da LGPD e OWASP Top 10) e usabilidade administrativa.

Back-end API (Laravel 11)
API RESTful em PHP 8.3/8.4, padronizada integralmente em inglês, com controle de concorrência, ofuscação de IDs (anti-IDOR), criptografia em repouso com blind indexing e esteira automatizada com 60 testes passando.
Front-end Admin (React 19 + TypeScript)
Single Page Application (SPA) estilizada com Tailwind CSS v4 e empacotada via Vite, compilada diretamente para a pasta estática do Laravel (backend-api/public/admin) para deploy unificado.

2. Arquitetura do Back-end (backend-api)

2.1 Tecnologias e Configuração do Servidor

  • Linguagem & Framework: PHP 8.3 / 8.4 com Laravel 11.
  • Porta Dedicada: SERVER_PORT=8001 (URL base: http://localhost:8001), isolando o projeto da porta 8000.
  • Banco de Dados: MySQL 8.x (banco Coturno_Cia, charset utf8mb4_unicode_ci).
  • Autenticação de APIs: Laravel Sanctum com tokens Bearer de expiração em 8 horas e revogação dinâmica.

2.2 Banco de Dados e Migrations Unificadas

A estrutura de banco de dados passou por uma consolidação arquitetural, substituindo migrações fragmentadas e duplicadas por 23 migrations unificadas totalmente padronizadas em inglês. Todas as 30 tabelas legadas temporárias (prefixadas com legacy_*) foram limpas em definitivo via migration de descarte seguro, mantendo a integridade referencial intacta.

Tabela Finalidade Destaques do Esquema
users Usuários do sistema (clientes e administradores) role ('customer', 'admin'), active (bool), cpf_hash, CPF/telefone cifrados, SoftDeletes.
products Catálogo de calçados e equipamentos base_price (venda), cost_price (custo), promotional_price, SoftDeletes, slug único.
product_sizes Grade de numeração e controle de estoque size (ex: 37 a 44), stock (quantidade por numeração), chave estrangeira para products.
product_prices Histórico auditável de precificação price, cost_price, effective_date, created_by (ID do administrador que alterou).
orders & order_items Pedidos e itens faturados order_number gerado, restrição de exclusão de produtos vendidos (RESTRICT), status enum em inglês.
audit_logs Trilha de auditoria imutável (LGPD) Tabela append-only: actor_label, action, old_values, new_values, IP e User-Agent.

2.3 Mecanismos de Segurança e Conformidade LGPD

Ofuscação de IDs (Anti-IDOR / Anti-Scraping)
Implementado através da Trait HasHashid. As chaves primárias numéricas nunca vazam em endpoints JSON, sendo codificadas em strings alfanuméricas de 22 caracteres com namespace individual por tabela. Um ID de pedido não funciona como ID de usuário.
Criptografia em Repouso & Blind Index
Campos sensíveis (CPF, telefone, nascimento) utilizam o Cast SafeEncrypted com cifras AES-256-CBC. Para viabilizar buscas exatas sem descriptografar em massa, gera-se um cpf_hash via HMAC-SHA256, mantendo o CPF mascarado na listagem.
Auditoria Append-Only: A tabela audit_logs lança exceções fatais em tentativas de UPDATE ou DELETE. Além disso, antes de persistir alterações cadastrais, o serviço AuditLogger sanitiza e mascara automaticamente senhas, CPFs e e-mails.

3. Arquitetura do Front-end (front-end admin)

3.1 Tecnologias e Organização

  • Core: React 19 com TypeScript estrito, garantindo type-safety em todos os formulários e chamadas de API.
  • Roteamento: React Router Dom v7 com componente de ordem superior RequireAuth para proteção de rotas restritas.
  • Design System: Tailwind CSS v4 configurado com cores personalizadas (army, pretoclaro, etc.) e ícones com Lucide React.
  • Autenticação do Painel: Módulo src/lib/auth.ts gerenciando token Bearer e cabeçalhos automáticos com redirecionamento em caso de 401/403.

3.2 Telas e Módulos Operacionais

1. Tela de Login (/admin/login)
Interface de login intuitiva contendo a listagem de todos os administradores cadastrados com seus cargos e senhas padrão. Inclui mecanismo de Auto-fill em 1 clique: ao tocar em um administrador, e-mail e senha são preenchidos instantaneamente.
2. Catálogo de Produtos
Gestão completa do catálogo com tabela que exibe Preço de Venda e Preço de Custo, grade de tamanhos, cores e estoque. O formulário de criação/edição permite ajustar preços, anexar fotos via Cloudinary e ativar/inativar produtos.
3. Gestão de Pedidos
Visão analítica de pedidos recebidos com número de identificação ofuscado, comprador, total faturado e método de pagamento. Permite a atualização dinâmica de status (Pendente, Processando, Enviado, Entregue, Cancelado).
4. Gestão de Usuários & Auditoria
Controle de clientes e administradores com busca por CPF protegido, criação de administradores com senha temporária descartável, alteração de status/role e visualização de trilhas de auditoria (quem fez, quando e o que mudou).

4. Comunicação e Integração Front/Back

O front-end administrativo compila de forma automatizada para backend-api/public/admin/ por meio do Vite (outDir: '../../backend-api/public/admin'). O Laravel serve os arquivos estáticos diretamente quando o usuário acessa http://localhost:8001/admin, eliminando problemas de CORS em ambiente integrado e simplificando o processo de deploy.

Ação Operacional Endpoint API (Laravel) Método Proteção / Middleware
Autenticação Admin /api/v1/auth/login POST Público (Rate Limited / throttle:login)
Listagem de Produtos /api/v1/produtos ou /api/v1/products GET Sanctum + Admin (Ofuscação Hashid)
Cadastro de Produto + Preço Custo /api/v1/produtos ou /api/v1/admin/produtos POST Sanctum + Admin + Transação DB
Alteração de Preço / Custo /api/v1/produtos/{id} PUT Sanctum + Admin + Histórico de Preços
Busca por CPF Seguro /api/v1/admin/usuarios/buscar-cpf GET Sanctum + Admin + Blind Index (HMAC)
Trilha de Auditoria /api/v1/admin/logs GET Sanctum + Admin (Somente Leitura)
